# TG WS Proxy для Android

Android-порт [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy). Приложение запускает на телефоне
локальный MTProto-прокси (`127.0.0.1:1443`), а Telegram подключается к нему как к обычному прокси.
Трафик уходит к серверам Telegram через WebSocket, а при блокировках — по запасным путям
(Cloudflare Worker, Cloudflare, TCP) и, на мобильном интернете, через встроенный WARP-туннель.

Ядро прокси **написано на Rust** (папка [`rust-core/`](rust-core)), интерфейс — на Jetpack Compose.

## Установка

Скачайте APK из раздела [Releases](../../releases/latest) и установите на телефон
(Android разрешит установку из неизвестных источников один раз). Дальше приложение
обновляется само — см. [Автообновление](#автообновление).

Требования: Android 7.0+ (minSdk 24), 64-битный процессор (arm64-v8a).

## Первый запуск

При первом открытии приложение показывает короткую инструкцию из пяти шагов (позже её можно
открыть кнопкой **«Как пользоваться»** на вкладке **«Ещё»**):

1. Что это за приложение.
2. Нажать большую кнопку питания на главном экране.
3. Нажать **«Добавить в Telegram»** и подтвердить.
4. Отключить оптимизацию батареи, чтобы Android не останавливал прокси в фоне.
5. Что делать, если на мобильном интернете не работает (WARP).

## Если не работает на мобильном интернете

Некоторые операторы режут соединения до адресов Telegram и фильтруют публичные домены Cloudflare.
На Wi-Fi прокси при этом работает. Вкладка **«Сеть» → «Проверить связь»** показывает, какие пути живы.
Если все красные, есть два рабочих способа:

1. **Встроенный WARP (рекомендуется).** Получите бесплатный конфиг на
   [warp-generation.github.io](https://warp-generation.github.io/) (подойдёт AmneziaWG; для мобильных сетей
   выбирайте серверы `[LTE]`), затем в **«Настройки» → «WARP»** загрузите файл и включите переключатель.
   Туннель включается сам, когда телефон на мобильном интернете, и выключается на Wi-Fi. Если Telegram режется
   и на Wi-Fi, включите переключатель «Использовать WARP и на Wi-Fi»; чтобы отключить WARP полностью, выключите
   оба переключателя. В него идут только
   Telegram-клиенты и это приложение, остальной телефон работает как обычно. Если уже включён другой VPN,
   туннель ждёт, пока он выключится (в Android одновременно работает только один VPN).
2. **Свой Cloudflare Worker на своём домене.** Укажите домен в **«Настройки» → «Домены Cloudflare Worker»**.
   Порядок попыток при сбое прямого пути: Worker → Cloudflare → TCP. Инструкция по созданию Worker —
   в документации [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy).

Если вы уже пользуетесь VPN-приложением (например, Happ), приложение само замечает VPN, сбрасывает
старые соединения и работает через него.

## Особенности для телефона

- **Сброс при смене сети.** Сервис следит за `ConnectivityManager`. При переключении LTE ↔ Wi-Fi ↔ VPN
  закрываются пул и активные сессии, и Telegram переподключается сразу, а не ждёт таймаутов.
- **Быстрое подключение.** Пути к Telegram (прямой WebSocket, Cloudflare, TCP) пробуются параллельно с короткими
  таймаутами, а путь, сработавший в прошлый раз, пробуется первым — первый коннект больше не ждёт мёртвые маршруты.
- **Пул соединений** по умолчанию 8 на дата-центр (1–16), с отдельным профилем для Wi-Fi, если включить.
- **Cloudflare по порту 80** (идея из [amurcanov/tg-ws-proxy-android](https://github.com/amurcanov/tg-ws-proxy-android)):
  операторы часто режут TLS:443 до Cloudflare. Режим `auto` сначала пробует 443, при неудаче 80 и запоминает
  выбор на 10 минут.
- **Сторожевой таймер**, **wake lock** (переключатель «Не давать телефону засыпать»), автозапуск после
  перезагрузки и обновления.
- Плитка быстрых настроек, уведомление при сбоях, «Поделиться логом» (секрет и домены в логе скрываются),
  экспорт и импорт настроек.

## Ядро на Rust

Крейт [`rust-core/`](rust-core) (лицензия MIT) подключается к приложению через JNI. Внутри: обфускация
MTProto (abridged, intermediate, padded; клиенты с secret `dd`), пул прямых WebSocket-соединений с подменой
SNI, цепочка Worker → Cloudflare (TLS:443, затем порт 80) → TCP, **Fake-TLS** (secret `ee`, настройка
«Fake-TLS домен»: пробы и повторы уходят на настоящий сайт-маску), **HTTP/2-линия для медиа** через
Cloudflare (`kws<DC>.<домен>/api`, с повторной отправкой пакетов для получения ответов) и **автозагрузка списка
доменов Cloudflare** (раз в час, если свои домены не заданы). Плюс статистика, лог, смена размера пула без
перезапуска и проверка связи.

## Десктоп (Windows, Linux, macOS)

Это же Rust-ядро собирается как консольная программа `tgws`:

```bash
cd rust-core
cargo run --release --bin tgws -- --port 1443
```

На Windows можно запустить `tgws.bat` (нужен [Rust](https://rustup.rs)). Программа сама создаст secret и выведет
ссылку `tg://proxy?...`. Опции: `--pool-size`, `--cfproxy-domain`, `--cfproxy-worker-domain`, `--fake-tls-domain`,
`--no-h2`, `--no-secure`, `--force-test-dc`, `--proxy-protocol`, `--log-file` с ротацией, `-v`; раз в минуту в лог
пишется статистика. Все опции: `tgws --help`.

## Автообновление

Приложение проверяет последний [релиз](../../releases/latest) при открытии (не чаще раза в 6 часов)
и раз в 12 часов, пока работает прокси. Если версия новее, APK скачивается (по умолчанию только по Wi-Fi)
и приходит уведомление «Нажмите, чтобы установить». Android всегда просит подтвердить установку.

Версия приложения: `<версия ядра>[.<ревизия>]`, например `1.11.4` или `1.11.4.1`.

## Сборка

Нужны JDK 17, Android SDK, Android NDK 26, Rust (`rustup`) и `cargo-ndk`:

```bash
rustup target add aarch64-linux-android
cargo install cargo-ndk
cd android
./gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

Gradle сам запускает `cargo ndk` для `rust-core`. Список архитектур задаётся в `android/gradle.properties`
(`abis=arm64-v8a`). `android/local.properties` с путём к SDK создаётся локально и в репозиторий не попадает.

Готовый APK собирается и в GitHub Actions (workflow [Build Android APK](.github/workflows/android.yml),
запуск вручную через *Run workflow*).
