# TG WS Proxy для Android

Android-порт [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy): то же ядро
`proxy/`, но в виде приложения. Прокси работает как foreground-сервис на
`127.0.0.1:1443`, Telegram подключается к нему как к обычному MTProto-прокси.

Python-ядро запускается внутри приложения через [Chaquopy](https://chaquo.com/chaquopy/)
(Python 3.12), отдельный интерпретатор или Termux не нужен.

## Установка

Скачайте APK из раздела [Releases](../../releases/latest) и установите на телефон.

Требования: Android 7.0+ (minSdk 24), **arm64-v8a** (все телефоны с 2016 года).
32-битные устройства не поддерживаются — Python 3.12 в Chaquopy существует только
для 64-битных ABI.

Дальше приложение обновляется само — см. [Автообновление](#автообновление).

## Использование

1. Открыть приложение и нажать **«Запустить»** — Android покажет уведомление о
   работе foreground-сервиса.
2. Нажать **«Добавить в Telegram»** — прокси подхватится автоматически.
3. Нажать **«Отключить оптимизацию батареи»**, иначе система будет выгружать сервис
   из памяти.

Настройки (порт, secret, IP дата-центров, Cloudflare-резерв, домены Cloudflare
Worker, автозапуск, подробный лог) применяются при следующем запуске. Приложение
интерфейсно на русском и английском.

### Домены Cloudflare Worker

Поле **«Домены Cloudflare Worker (через запятую)»** — это резервный путь, а не
ускорение. Ядро использует его только если прямое подключение к DC Telegram
сорвалось (порядок попыток: `cf_worker → cf → tcp`). Пока прямой канал жив, Worker
не участвует.

Домен берётся из своего Cloudflare Worker, инструкция по его созданию —
[docs/EN/CfWorker.md](docs/EN/CfWorker.md). Несколько доменов перечисляются через
запятую или с новой строки, пустое поле выключает резерв.

## Мобильная сеть

Ядро рассчитано на десктоп, поэтому Android-обёртка (`android_entry.py` и
`ProxyService`) добавляет то, что нужно телефону в сотовой сети (за CGNAT оператора,
со сменой вышек и переключением LTE ↔ Wi-Fi). Само ядро `proxy/` при этом не
изменяется:

- **Keepalive и таймаут «мёртвых» соединений.** Сокеты к Telegram получают
  `SO_KEEPALIVE` (проба через 25 с тишины, интервал 10 с, 3 попытки) и
  `TCP_USER_TIMEOUT` 35 с. Соединение, которое оператор молча сбросил, обнаруживается
  за десятки секунд, а не за минуты.
- **Сброс при смене сети.** Сервис следит за `ConnectivityManager`. Если сеть
  действительно сменилась (LTE ↔ Wi-Fi), закрываются пул и активные сессии, и Telegram
  переподключается сразу, а не ждёт таймаутов. Если та же сеть просто «моргнула», сбрасывается
  только пул, а живые сессии остаются. Затем пул прогревается заново.
- **Пул соединений 6 на DC** (в ядре по умолчанию 4) и буфер сокета 512 КБ. Пока в пуле
  есть готовое соединение, Telegram идёт напрямую по WebSocket; когда Telegram открывает
  параллельно больше соединений, чем в пуле, лишние уходят на более медленный запасной путь
  (Cloudflare или TCP). Размер пула меняется в настройках (1–16).
- **Интерфейс не блокируется прокси.** Статистика и лог читаются из Python в фоновом
  потоке, а сам Python прогревается при запуске приложения.
- **Сторожевой таймер.** Раз в 20 с проверяется, что ядро живо; если упало —
  перезапускается.
- **Wake lock** (переключатель «Не давать телефону засыпать», по умолчанию включён)
  не даёт Doze отрезать сеть в фоне. Расходует немного больше батареи.
- Автозапуск после перезагрузки и после обновления приложения.

На главном экране видны скорость, график и диагностика: сколько сессий пошло напрямую
(WS), через Cloudflare (CF) и по TCP, и процент попаданий в пул. Если CF и TCP растут, а WS
нет, прямое соединение до Telegram у вашего оператора не работает или пул слишком мал.

Для сетей, где прямое подключение к Telegram режется, остаются резервные маршруты
ядра: Cloudflare-прокси и свой Cloudflare Worker (см. выше).

Всё это проверено только на уровне логики Python-части; поведение у конкретного
оператора зависит от его DPI и фильтров, поэтому при проблемах включите
«Подробный лог» и посмотрите раздел «Лог» в приложении.

## Вкладки и новые функции

Внизу четыре вкладки: **Главная**, **Сеть**, **Настройки**, **Ещё**.

- **Проверка соединения** — замеряет время до Telegram по каждому маршруту (WS, TCP, Cloudflare) и говорит, что работает.
- **Счётчик трафика** — сегодня и за месяц, отдельно Wi-Fi и мобильная сеть.
- **Профили сетей** — свой размер пула для Wi-Fi и мобильной сети, переключается автоматически.
- **Плитка быстрых настроек**, уведомление при сбоях, «Поделиться логом», экспорт/импорт настроек.
- **Cloudflare по порту 80** (идея из [amurcanov/tg-ws-proxy-android](https://github.com/amurcanov/tg-ws-proxy-android)): мобильные операторы часто режут TLS:443 до Cloudflare. Режим `auto` сначала пробует 443 за ≤4 с, при неудаче идёт по 80 и запоминает выбор на 10 минут.
- По умолчанию WS-пул включён для DC 1–5 (раньше только 2 и 4), чтобы меньше соединений падало в медленный fallback.

## Автообновление

Приложение проверяет последний [релиз](../../releases/latest) этого репозитория:
при открытии (не чаще раза в 6 часов) и раз в 12 часов, пока работает прокси.
Если версия новее, APK скачивается (по умолчанию только по Wi-Fi) и приходит
уведомление «Нажмите, чтобы установить». Android всегда просит подтвердить установку
сам; при первом обновлении нужно один раз разрешить установку из приложения.

Версия приложения — `<версия ядра>[.<ревизия>]`, например `1.11.4` или `1.11.4.1`
(исправление приложения на том же ядре).

### Как выпустить релиз

Чтобы обновление установилось поверх прежнего APK, **все релизы должны быть подписаны
одним и тем же ключом**. Для этого в *Settings → Secrets and variables → Actions*
добавьте секреты:

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore в base64: `base64 -w0 your.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль keystore |
| `ANDROID_KEY_ALIAS` | алиас ключа |
| `ANDROID_KEY_PASSWORD` | пароль ключа |

Если вы уже установили APK, собранный локально, он подписан вашим debug-ключом
(`~/.android/debug.keystore`, пароль `android`, алиас `androiddebugkey`). Используйте
именно его в секретах — тогда первое автообновление встанет поверх без удаления
приложения. Если подписать другим ключом, Android откажется обновлять: придётся один
раз удалить приложение и поставить заново.

Затем создайте тег и отправьте его:

```bash
git tag v1.11.4
git push origin v1.11.4
```

Workflow соберёт APK (только `arm64-v8a`, чтобы обновление было меньше) и
опубликует релиз. Без секретов релиз намеренно не создаётся — такой APK нельзя
было бы установить поверх прежнего.

## Сборка

Нужны JDK 17, Android SDK (platform 34, build-tools 34) и Python 3.12 в `PATH` —
Chaquopy использует его для `pip`.

```bash
cd android
./gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```

`android/local.properties` с путём к SDK создаётся локально и в репозиторий не
попадает. Ядро `proxy/` при сборке копируется задачей `syncProxyCore` в
`android/app/src/main/python/proxy` — эта папка генерируется и тоже не коммитится.

Готовый APK также собирается в GitHub Actions (workflow
[Build Android APK](.github/workflows/android.yml), запуск вручную через
*Run workflow*).

## Отличия от исходного порта

Проект собирался локально, и три вещи в исходной версии не давали сборке пройти:

1. **`python.srcDir(...)` в `app/build.gradle.kts`** — Chaquopy не предоставляет
   типизированный доступ к Python source set из Kotlin DSL, скрипт не компилировался.
   Заменено на копирование ядра напрямую в `src/main/python/proxy`.
2. **`armeabi-v7a` в `abiFilters`** — Python 3.12 для этого ABI не существует,
   сборка падала с `Python 3.12 is not available for the ABI 'armeabi-v7a'`.
   ABI сокращены до `arm64-v8a` и `x86_64`.
3. **Неявная зависимость задачи** — Gradle ругался, что `mergeDebugPythonSources`
   читает выход `syncProxyCore` без объявленной зависимости. Добавлен `dependsOn`.

Дополнительно добавлено поле для доменов Cloudflare Worker, которого в порте не
было, хотя ядро его поддерживает.

## Проверено

Собрано и запущено на Redmi 22101320G (Android 14, arm64-v8a): сервис поднимается,
порт `127.0.0.1:1443` слушается, Telegram держит через него соединения, ошибок в
logcat нет.

Версия с обновлённым ядром (1.11.4), новым дизайном, мобильной устойчивостью и
автообновлением написана без возможности собрать и запустить Android-часть, поэтому
на устройстве не проверена: Python-часть прогнана локально, Kotlin и ресурсы — нет.
